<a id="routes"></a>
## 1. 先分清：代码动画和 AI 素材动画

制作前先选路线，否则容易把“用代码导出视频”误解成“所有画面都必须由几何图形画出来”。

| 路线 | 主要素材 | 适合的内容 | 需要先解决的问题 |
|---|---|---|---|
| 纯代码动画 | 文字、图形、粒子、图表、程序绘制的场景 | 歌词动效、知识解释、产品演示 | 时间线、排版、动作与节奏 |
| 图像加代码动画 | 参考图、角色图、场景图，再用代码控制运动和合成 | 风格化 MV、海报动画、叙事短片 | 角色与场景一致、构图、图层关系 |
| 视频素材加代码合成 | 实拍或生成的视频片段，再叠加文字、图形与转场 | 表演镜头、复杂人物运动、混合媒介 MV | 音画同步、片段质量、合成连续性 |

Donald 的原提示词包含角色与场景素材、视频生成、JavaScript 动画、文字设计和反复检查等想法；anabology 的原帖说明在 Donald 提示词之外还用了 Midjourney 和视觉参考板。它们可以启发混合制作流程，但不能据此认定“一句提示词就能稳定复刻同一成片”。[原提示词](https://x.com/donaldjewkes/status/2102801469976248500)、[anabology 原帖](https://x.com/anabology/status/2103534482930491441)。

对第一次制作的人，建议从**十几秒、一个视觉主题、一个完整乐句**开始。先把一个段落做完整，再沿着同一套风格扩展。

<a id="inputs"></a>
## 2. 十分钟开工：准备这些输入

### 必需材料

1. **音频文件**：尽量使用原始音频，说明能否剪短、是否允许改速。MV 通常先锁定音乐，再安排画面。
2. **歌词或文字稿**：最好有时间码；没有时先校对内容，再对齐。不要让模型只凭听感猜专有词。
3. **视觉参考**：准备少量有明确用途的图片或视频。分别说明参考的是颜色、构图、运动还是文字排版。
4. **作品规格**：用途、观众、横竖比例、分辨率、帧率、目标时长。
5. **可用工具**：现有编程助手、图像或视频工具、渲染环境。具体服务是否能用，开工时现场检查。

### 可直接填写的需求单

```text
作品名称：
给谁看：
看完要记住的一件事：
作品类型：纯代码动画 / 图像加动画 / 视频加合成
音频文件：
歌词或文字稿：
视觉参考及分别参考什么：
固定主角与识别特征：
时长：完整歌曲 / 约多少秒的节选
画幅与导出规格：例如 1920×1080、30fps、MP4
必须保留：
不希望出现：
已具备的工具与素材：
允许新增的付费素材预算：
交付内容：成片、源工程、素材清单、说明
```

参考图不是越多越好。两组互相冲突的风格会让作品来回变化；每个参考都应有具体职责。角色、服装、颜色和字幕样式一旦选定，应写进一份风格说明，后面各段共用。

<a id="workflow"></a>
## 3. 完整制作流程：从样片到成片

### 第一步：先理解音乐和内容

把歌曲划分成前奏、主歌、副歌、过渡与结尾，并标出每段起止时间。再圈出重要的鼓点、停顿、情绪变化和需要视觉强调的词。

这一步至少得到三样东西：

- 校对过的歌词或字幕稿。
- 带时间码的段落表。
- 一句可以贯穿全片的视觉主线。

如果音频识别结果与实际内容不一致，先修文字，暂时不要往后堆动画。

### 第二步：把风格说具体

用可检查的描述代替“高级、震撼、电影感”。例如：

> 黑色和暖白为主，橙红只标重点；主角保持同一发型和服装；画面保留颗粒质感；副歌放大歌词；主歌优先完整表达场景，避免每一拍都切镜。

这是一个可替换的示例，不是所有 MV 的固定模板。你的参考可以是轻松、明亮、像素风或极简图形，但整段内容应有一致的视觉规则。

### 第三步：先做十几秒样片

样片应包含一个完整小段，而不是只生成一张漂亮的开场图。至少检查：

- 主体是否稳定，角色是否容易辨认。
- 文字放在真实画面上能否看清。
- 动作和切镜是否跟着音乐变化。
- 能否实际导出可播放的视频。

样片方向不对，就先改风格或分镜。不要等整首歌渲染完，才发现角色、色彩或字幕都要重做。

### 第四步：写成分镜表

下面只是结构示例，秒数需要根据自己的音乐重算：

| 时间 | 音乐与内容 | 画面 | 文字 | 进入下一镜的依据 |
|---|---|---|---|---|
| 0—4 秒 | 建立主题 | 主要角色或核心图形出现 | 一句核心文字 | 第一个明显音乐转折 |
| 4—12 秒 | 展开第一件事 | 场景或图形随内容变化 | 重点词与少量字幕 | 语义或乐句完成 |
| 12—20 秒 | 情绪上升 | 景别、构图或运动升级 | 更明确的主题词 | 段落变化 |
| 20 秒以后 | 按音乐继续 | 复用视觉主线并变化 | 服从画面与歌词 | 以实际音频为准 |

每个镜头还应写清需要哪些素材、哪些元素运动、什么时刻出现。时间线不要只记录“这里很燃”，而要能指导制作。

### 第五步：做素材，再做动画与合成

有角色时，先做一张稳定的角色设定图，再扩展不同表情和景别；有场景时，统一色调、光线和透视。把最终选择的素材收进工程，避免每次渲染时随机换一张图。

用代码制作动画时，把画面定义为时间的函数：输入同一时刻，应得到同一画面。这样可以准确抽查某一帧，也方便修改某一段而不影响其他段落。需要随机效果时固定随机种子；如果环境支持，使用固定时间步长导出。

图形不是越多越好。给每个元素一个职责：介绍主体、解释内容、表现节奏，或者完成转场。长期没有作用的粒子、边框和浮动文字可以删掉。

### 第六步：单独修字幕与节拍

字幕有两种常见职责：

- **信息字幕**：把观众需要理解的话准确呈现出来，位置稳定，停留足够。
- **歌词动效**：让少量重点词成为画面的一部分，配合声音与动作。

不要让每一句都用最大字号、最强动效。先保证歌词正确、进入和退出的时刻合理，再决定哪些词值得强调。画面复杂时减少文字变化；文字承担主要叙事时，背景相应简化。

### 第七步：导出后检查真实文件

预览页面能动，不代表导出的 MP4 正常。检查实际成片的首帧、转场、字幕边缘和末帧，并完整播放声音。

音乐作品尤其要检查：有没有切掉一个字的尾音，嘴形是否对应声音，副歌结束后是否误带入下一句，画面停止与音频结束是否协调。把问题定位到时间码，再做修改。

<a id="master-prompt"></a>
## 4. 可复制的中文 MV 总提示词

下面是为实际制作重新写的中文模板。替换方括号后再使用；它不是 Donald 原帖的逐字译文。需要原始全文时，可以直接打开[GitHub 收录页](https://github.com/yihui-dev/awesome-opus5-5-videos/blob/1c092195b7bda246455827bc0be820be6d6a7b97/prompts/anabology-491441.md)。

```text
请作为这支视频的导演、动画设计师和制作工程师，完成一个可以实际导出的音乐视频项目。

【我的输入】
作品主题：[主题]
观众：[观众]
音频：[文件路径]
歌词或文字稿：[文件路径；没有时请先识别并标出不确定内容]
视觉参考：[文件路径或链接，并说明各自参考什么]
主角与固定特征：[没有人物则写无]
画幅、分辨率、帧率：[规格]
目标时长：[整首歌，或约多少秒]
已具备的工具：[工具列表]
新增付费素材预算：[金额；未填写时不新增付费调用]
最终输出目录：[目录]

【先完成计划与样片】
先检查输入文件和可用工具，说明能够实际运行的制作路线。
分析音频结构与歌词，给出带时间码的段落表。
提出一个贯穿全片的视觉主线，并用具体的颜色、构图、角色、文字与运动规则描述它。
参考材料只吸收明确的设计特点，不照搬品牌标识或整套镜头。
先做一个十几秒的完整样片，覆盖主体、文字、动作和一次真实导出。
若用户已有明确风格和参考，就沿着它完成样片；有影响方向的歧义时，集中列出需要补充的内容。

【素材与场景】
如果包含角色，先建立角色设定，固定脸型、发型、服装和关键配色。
如果使用图像或视频生成，先列素材清单，记录每个素材的用途和所用工具。
将已选素材固定在工程中，不要在每次渲染时随机替换。
不能使用某个外部工具时，明确标注缺口，并给出利用现有素材的可执行方案。
同一段落中的人物、环境、光线与图形风格应保持一致。

【镜头与时间线】
用时间码列出每个镜头的内容、素材、运动、字幕和转场依据。
根据音乐和语义决定镜头长度，不做机械的等间隔切镜。
在需要观看主体或阅读文字时保持稳定，情绪变化时再改变景别和运动。
同一主题用视觉变化递进表达，避免反复放同一张图而没有信息进展。
开头尽快让观众看懂主体；后面的内容要兑现开头展示的主题。

【文字与动画】
区分信息字幕和歌词动效，优先保证内容准确、可读且与声音同步。
重点词可以成为构图的一部分，其他文字不与主角或背景争抢注意力。
文字留在安全区内，不盖住主要动作。
用明确的时间线驱动动画，同一时间点应可以稳定复现同一画面。
保留可编辑的参数，不把所有坐标、颜色和字幕时刻散落在无法维护的代码里。

【音频】
以提供的音乐为基准。未经本次需求允许，不改旋律、唱词、音高或播放速度。
需要表演或口型时，先检查片段是否能与对应歌词对齐。
先保证音画同步，再处理音量和必要的音效。
如果做节选，在目标时长附近找完整句子或乐段结束点，不按整数秒硬切。
保留必要尾音和末帧停留，避免提前黑屏或带入下一句再突然结束。

【检查与迭代】
先输出低分辨率检查版，检查结构、字幕、节拍和素材连续性，再导出正式版本。
按时间码列问题、原因和修改方案。每轮优先修最影响观看的几项。
检查真实导出文件，而不只检查编辑器或浏览器预览。
修改使用新版本，保留上一次可用结果和素材映射。
没有完成的检查必须写清楚，不把渲染成功当作内容验收通过。

【最终交付】
1. 可播放的 MP4。
2. 可编辑的源工程与运行说明。
3. 素材清单、来源和时间线。
4. 实际检查结果与尚待处理的问题。
请先输出你对任务的理解、素材缺口、分镜计划和样片范围，再开始制作。
```

原帖里的私人目录、账号额度和预算属于原作者当时的环境，不应直接复制到自己的任务里。上面的模板将它们改成了需要你明确填写的参数。

<a id="stage-prompts"></a>
## 5. 分阶段提示词：分镜、样片、精修与验收

不想一次交给模型整首歌，可以按以下顺序拆开。

### A. 先分析音频和分镜

```text
先不要生成全片。
读取我提供的音频、歌词和参考，做一个带时间码的分镜方案。
每个镜头写清：开始与结束时间、这段表达什么、主体、素材、动作、字幕、切镜理由。
指出哪些歌词或时间码还需要人工确认。
选出一个十几秒、能代表全片风格的小段作为样片。
```

### B. 样片定方向

```text
按已经确定的分镜，只制作样片这一段。
使用真实素材、字幕与音频，实际导出一个可播放文件。
同时给出首帧、中间帧、末帧和手机尺寸预览。
自检角色一致性、文字可读性、音画同步、首尾完整性。
不要仅交静态效果图，也不要顺手扩展到整首歌。
```

### C. 按时间码修改

```text
基于当前可用版本修改，不重做未点名的部分。
问题时间码：[填写]
当前问题：[填写具体看到或听到的现象]
希望改变：[填写]
必须保留：[填写]
先解释你认为的原因和改动范围，完成后导出新版本，并列出实际检查结果。
```

### D. 收尾与验收

```text
检查最终导出的 MP4：
核对首帧是否完整，所有素材和字幕是否能显示，音频是否与画面对齐。
重点检查切镜前后、密集文字、段落结束以及最后两秒。
若要求大致时长，在附近选择完整语句或音乐段落结束点，保留尾音。
给出实际分辨率、帧率、时长、音视频编码、完整解码结果和未完成的人工检查。
不要将检查脚本通过写成已经完整人工听看。
```

<a id="comparison"></a>
## 6. 同一提示词比较模型：一个可操作的新示例

JAZII 的[原帖](https://x.com/notjazii/status/2103884167104831573)展示了四个模型在其所称“同一提示词”下的动画结果。公开正文没有给出完整实验提示词和足够的运行设置，因此下面是**新写的对比练习**，不是对原实验的复现，也不据此给模型排名。帖子里的未发布版本与上线时间说法仍属于作者陈述。

### 对比时固定什么

| 项目 | 怎么固定 |
|---|---|
| 提示词 | 每个模型使用完全相同的文本 |
| 输入 | 相同图片、音频、尺寸和资源限制 |
| 环境 | 相同浏览器、输出规格和可用依赖 |
| 修改机会 | 区分一次生成与允许修正后的结果，次数一致 |
| 评判 | 同时看完成度、错误和交付能力，不只看一张截图 |

### 可直接复制的代码动画练习

```text
制作一个12秒、1280×720的像素风海边列车动画。
只使用HTML、CSS和JavaScript Canvas，在单个HTML文件中实现。
不加载外部图片、字体、视频或网络资源，不加入声音。

场景：黄昏海岸，一列短火车沿海边轨道前进。
画面必须包含前景轨道、中景列车、远景海面和天空。
不同距离的图层有不同移动速度；海面有轻微反光，列车有稳定的运动。
整片保持有限色板和统一像素尺寸，避免混入平滑矢量线条。
前两秒建立场景，中段让主体充分展示，最后两秒形成自然结束。

代码应使用统一时间变量计算动画，提供renderFrame(t)接口，t的单位是秒。
renderFrame(t)连续调用或跳到同一t时，都应得到相同画面。
不依赖真实墙钟，不让反复调用积累对象数量。
输出完整HTML及简短运行说明，并检查语法与控制台错误。
```

`renderFrame(t)` 是本练习约定的项目接口，并非浏览器内置 API。它让抽帧和对比更方便，但仍需另配录制或逐帧导出流程。

评估时可以按 0—2 分记录：是否能运行、必需元素是否齐全、风格是否一致、运动是否稳定、能否准确跳转到时间点、是否完成自然收尾。把原始输出与修改后输出分别保存，避免把“多轮精修结果”当成“一次生成表现”。

<a id="export"></a>
## 7. 导出与技术检查

不同工程可能使用不同的导出工具。代码动画可以由已有渲染器、浏览器录制或固定时间步长抽帧生成视频；图像和视频素材则按时间线合成。先让样片跑通一条可执行路径，再扩大制作规模。

下面的 FFmpeg 命令用于检查或封装已有文件，**它们本身不会把 HTML 自动变成视频**。运行前安装并确认 `ffmpeg`、`ffprobe` 可用。

### 查看实际参数

```bash
ffprobe -v error \
  -show_entries format=duration:stream=codec_type,codec_name,width,height,r_frame_rate \
  -of json final.mp4
```

### 将无声视频与音乐封装到一起

先确认两个输入已经从同一时间点开始，且时长相匹配；音画是否同步仍需要检查。

```bash
ffmpeg -i render-no-audio.mp4 -i song.wav \
  -map 0:v:0 -map 1:a:0 \
  -c:v copy -c:a aac -b:a 192k \
  -movflags +faststart final.mp4
```

### 检查文件是否能完整解码

```bash
ffmpeg -v error -xerror -i final.mp4 -f null -
```

### 定时抽帧辅助检查

```bash
mkdir -p qa
ffmpeg -i final.mp4 -vf "fps=1/5,scale=320:-1" qa/frame-%04d.jpg
```

定时抽帧可以发现漏图、越界和部分异常，但会错过短暂闪帧，也无法判断听感。还需要重点查看转场前后，并播放实际文件检查声音。

建议保留以下工程材料。目录名只是示例，不是本仓库已经附带的工程：

```text
project/
  brief.md           需求与规格
  style.md           风格、角色与文字规则
  timeline.json      镜头与字幕时间线
  assets/            已确定的素材
  src/               可编辑动画和合成代码
  renders/v001/      每版输出
  qa/                抽帧、检查结果与问题清单
```

<a id="portrait"></a>
## 8. 横版 MV 做成竖版视频

如果观众主要在手机上观看，可以在不裁掉原画面的情况下使用三段结构：

```text
┌──────────────────────┐
│       标题区          │
├──────────────────────┤
│  横版视频，等比展示     │
├──────────────────────┤
│   说明或提示词地址      │
└──────────────────────┘
```

一个参考规格是 1080×1920：上方标题固定，中间完整呈现横版素材，下方放一句说明或 GitHub 地址。上下用深色时，同时调整文字对比，不能只换背景让文字看不清。

本次配套竖版节选约 1 分 54 秒：在第一段 MV 的副歌完成后收住，保留短暂停留并淡出音乐，避开下一段的开头。这个剪点只适用于这条素材；换一首歌必须重新识别乐段，不能照搬秒数。

检查手机上最小的一行字，长网址可以拆成“域名／用户名”和“仓库名”，再标条目定位。图外说明不要与原视频自带字幕重叠。最后检查导出首帧，避免合成时间戳错位导致中间画面先空一帧。

<a id="troubleshooting"></a>
## 9. 常见问题与修改方法

| 问题 | 优先检查 | 具体修改 |
|---|---|---|
| 图很好看，整片却很散 | 是否有贯穿主线、分镜是否按音乐展开 | 先重排分镜，再调整装饰 |
| 同一个人一直变脸或换衣服 | 是否每段重新随机生成、是否缺少角色设定 | 固定角色参考和已选素材 |
| 字幕抢画面或读不完 | 字数、停留时间、与主体是否重叠 | 减少同屏信息，延长必要停留 |
| 节拍对不上 | 是否按真实音频定位，有没有混用不同起点 | 用统一时间线重新对齐 |
| 只能在预览里运行 | 导出方式是否提前验证、有没有网络资源依赖 | 先让短样片实际导出成功 |
| 全片变化很大，却没有重点 | 是否每一拍都强行切镜或放大文字 | 按内容区分稳定段与强调段 |
| 约两分钟的片段听起来被截断 | 是否机械剪在120秒、是否带入下一句 | 回到附近完整乐句，保留尾音 |
| 修改一处导致其他段失效 | 参数和时间线是否混在不可控代码里 | 拆清输入、样式、时间线与渲染，保留版本 |
