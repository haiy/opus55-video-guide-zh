# 按作品类型选择制作路线

[返回资源导航](resource-navigation.md) · [中文制作教程](../README.md)

先确定你已有的是歌曲、歌词、参考图、真实视频还是产品代码。输入不同，适合的制作路线也不同。

| 路线 | 画面从哪里来 | 编程助手主要做什么 | 首个验证目标 |
| --- | --- | --- | --- |
| 纯代码动画 | 文字、形状、笔刷、程序场景 | 编写绘制逻辑、时间线、动画与导出 | 一段画面可按指定时间稳定重现 |
| 图像加代码动画 | 参考图、生成图、角色与场景素材 | 组织图层、运镜、字幕、节拍和合成 | 一个人物和一个场景能保持一致 |
| 视频加代码合成 | 实拍或生成的视频片段 | 选择片段、编排镜头、叠加动效与音频 | 一段素材剪辑的字幕和声音正确同步 |
| 产品界面动画 | 真实组件、截图、录屏和版本变化 | 提炼卖点、放大操作、驱动界面与转场 | 观众能看清一个真实功能带来的变化 |

<a id="mv"></a>
## 音乐MV：先把歌曲和歌词锁定

输入：歌曲文件、校对后的歌词、视觉参考、希望保留的完整乐句。

顺序：音乐分段 → 节拍与歌词时间码 → 主角与风格 → 分镜 → 10—15秒样片 → 扩展全片 → 声音和字幕检查。

从[GitHub项目表](resource-navigation.md#github-项目)里的 PDoomVideo、ClaudeAnimationBase、paint-mv-skills、mexicat/pdoom-video 查找水彩、角色或歌词驱动的工程。需要外部图像和视频生成时，先看插件的素材输入与API依赖，不能直接沿用“纯代码生成每一帧”的说法。

本视频对应的 anabology 原帖提到了额外图像工具和参考板；Donald提示词是制作参考，不应被理解为不用素材、不用修改就能复刻同一作品。

<a id="product"></a>
## 产品宣传：把真实产品放进来

输入：产品代码或官网、目标观众、一个主要价值、真实界面、希望强调的更新。

顺序：核对真实功能 → 选择一个观看理由 → 操作特写与界面节奏 → 配乐和音效 → 实际导出。

在[项目导航](resource-navigation.md)中查找 brag、归藏 product video skill、Opus Video Studio。已有React界面时，也可查看Remotion；以HTML、SVG和DOM动效为主时，可查看HyperFrames与GSAP。

先用一个功能做短样片。确保宣传片中的界面与产品实际一致，再扩展成整支发布片。

<a id="explainer"></a>
## 科普与讲解：让画面承载解释

输入：准确文字稿、需要解释的机制、必要数据或公式、目标观众的前置知识。

顺序：确定一个问题 → 拆清过程 → 画出关键变化 → 配音与文字对齐 → 检查事实和阅读时间。

数学与几何图形可看Manim；时间线驱动的图解可看Motion Canvas；图文、真实素材和组件混排可看Remotion。模型写出的旁白与知识点需要独立核对，动画流畅不代表内容正确。

<a id="style"></a>
## 风格化短片：先定视觉规则

输入：故事梗概、人物、一个情绪转折、少量视觉参考。

先看Lemo-Opuscar风格目录，再看相应导演与技术指南；水彩可对照p5.brush，剪纸风可看papermotion，绘画笔触与音画同步可看painted-rickroll。

角色、配色、镜头和声音使用同一套规则。不要在同一片中无理由混用多个强风格。

<a id="finish"></a>
## 各路线共用的交付检查

1. 预览和导出使用同一时间基准，抽取同一时间点检查画面。
2. 声音先校准节拍、歌词和实际切口，保留完整尾音与乐句。
3. 中文字幕和外语字幕分别校对，不把自动识别结果直接当成歌词定稿。
4. 检查首帧、转场、信息最密的一帧和末帧；实际播放输出文件。
5. 保留素材说明、工程、字幕和导出参数，方便后续改稿。

这些是制作路线说明；本导航没有替你安装所有工具，也没有把收录项目视为已经实测可在任意机器上一键运行。工具的具体命令请跟随各项目当前文档。
